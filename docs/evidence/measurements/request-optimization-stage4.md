# 요청량 최적화 4단계 — 오래된 응답과 화면 수명 검증

확인일: 2026-10-21 21:39 KST. 비교 기준은 3단계 커밋 `40d59ad17419485dcec0f4153181c0a7ef3865db`이며 작업 브랜치는 `codex/request-optimization`이다. 운영 배포나 main 병합은 수행하지 않았다.

## 재현한 문제

수정 전에 실제 React 컴포넌트를 대상으로 12개 경합 시나리오를 실행했고, 그중 8개가 실패했다. 이는 8개의 독립적인 취약점이라는 뜻이 아니라 아래 원인들이 여러 조건에서 나타난 결과다.

1. **저장 전 조회의 늦은 오류:** GET이 진행 중일 때 PUT을 시작해도 GET의 조회 세대가 유효했다. PUT 성공 뒤 옛 GET의 401/403이 도착하면 저장한 팀 화면이 닫혔다. PUT이 아직 진행 중인 경우에도 옛 403이 화면을 지웠다. 낮은 revision의 성공 응답은 기존 보호가 이미 작동했다.
2. **로그아웃과 초기 로딩의 경합:** 로그아웃 후 페이지 이동/새로고침에만 의존했다. 이동이 완료되기 전에 정기 조회가 다시 실행되거나, Home이 TeamHub를 표시하던 중 시작한 초기 room 응답이 나중에 도착해 로그아웃한 화면에 팀을 다시 표시할 수 있었다.
3. **같은 revision의 권한 변화:** 새 권한으로 버튼은 바뀌더라도 이미 열린 관리 입력 창은 남아 있었다. 이전 관리자의 pendingJoinCount를 새 일반 팀원 응답에 이어 붙이는 경로도 있었다.
4. **페이지 이탈 시 조회 정리:** Home이 다른 팀 페이지로 바뀌어도 옛 room 조회가 취소되지 않았다. 새 컴포넌트와 옛 컴포넌트는 React 상태가 분리돼 있지만 불필요한 조회와 초기 로딩 후속 작업이 계속될 수 있었다.

수정 전 결과는 `request-optimization-stage4-before.json`에 보존했다. 이 파일은 수정 전 실행한 최초 12개 시나리오만 포함한다.

## 수정 내용

- Home의 변경 요청을 시작할 때 이전 room 조회를 무효화한다. 사용량 집계용 telemetry POST는 제외한다. 취소 신호를 무시하고 응답이 도착하는 경우에도 조회 세대 검사로 성공·오류를 모두 폐기한다.
- 명시적 변경 결과를 적용할 때도 이전 조회를 무효화한다. 변경 결과는 현재 열려 있는 같은 팀에만 적용하고, 권한 거부로 팀 화면을 닫은 뒤 옛 변경 결과가 팀을 다시 열지 못하게 한다. 팀을 여는 동작은 별도로 구분한다.
- 로그아웃 시작 시 room 조회를 중단한다. 성공 시 팀/관리 데이터와 인증 표시를 즉시 정리하고, 페이지 이동 완료를 기다리지 않고 이후 조회를 막는다. 실패 시 기존 화면과 정기 조회를 유지한다.
- TeamHub의 명시적 로그아웃/계정 종료를 Home에도 전달해 초기 로딩 요청까지 정리한다. 일반 비로그인 응답을 영구 종료로 취급하지 않으므로 다른 창에서 로그인한 뒤 돌아오는 정상 흐름은 유지한다.
- Home 초기 로딩에 개별 생명주기와 AbortController를 적용했다. 페이지 이탈 시 초기 인증/설정 조회와 room 조회를 취소하고 후속 작업을 차단한다. 개발 StrictMode의 effect 재실행에서도 다시 로딩한다.
- 권한·가입 신청 수는 revision이 같아도 새 응답을 반영한다. 관리 권한이 없으면 관리자용 신청 수를 제거하고, 관리/주장/기록 권한이 줄어들면 열린 관리 창과 관리 데이터를 정리한다.
- `getKakaoConfig`에 선택적인 AbortSignal 인자를 추가했다. 서버 API·쿠키·카카오 정책·DB 스키마·배포 설정은 바꾸지 않았다.

조회 조정기의 250ms 중복 이벤트 창, 15초 조회 시간 제한, 팀 3초·내 팀 15초의 정기 주기는 유지한다.

## 재현 방법과 한계

2단계에서 안내한 격리된 jsdom/fake-timers 설치 경로를 지정한다.

```sh
QUARTERMATE_MEASUREMENT_RUNTIME="측정 도구가 설치된 절대 경로" node scripts/measure-client-races.mjs work/request-races-stage4.json
QUARTERMATE_MEASUREMENT_RUNTIME="측정 도구가 설치된 절대 경로" node scripts/measure-client-requests.mjs work/request-measurement-stage4-regression.json
```

합성 계정·팀·응답을 사용한 React 가상 DOM 검증이다. 서버나 운영 DB/R2에 연결하지 않으며, 실제 카카오 로그아웃을 수행하지 않는다. 일부 시나리오는 취소 신호를 무시하는 합성 응답을 보내 세대 검사 자체가 작동하는지도 확인한다. navigation은 실제 브라우저 이동을 수행하지 않고 이동 요청을 기록하거나 컴포넌트를 새 팀 URL로 다시 마운트한다. 실제 모바일 브라우저에서의 검증, 복수 계정 검증, 운영 전체 트래픽·DB·CPU 실측은 이 검증의 범위 밖이다.

서버 접근 제어는 기존 백엔드 및 built Worker 검사로 함께 확인했다. 프론트의 오래된 표시를 정리하는 처리와 서버 권한 검증은 별개다. 후속 5단계는 경기 상태에 따른 갱신 주기 조절이며 실제 두 계정 동기화는 6단계에서 더 확인한다.
