# 요청량 최적화 3단계 — 중복 조회 제거

확인일: 2026-10-21 21:18 KST. 작업 브랜치 `codex/request-optimization`, 비교 기준은 2단계 `a9aa64750c5c1a1ef0cec6128a447d1e42d5397f`다. 운영 배포와 main 병합은 수행하지 않았다.

## 변경

- 팀 화면의 room 조회와 내 팀 화면의 account/workspace 조회에 컴포넌트별 조회 조정기를 적용했다. 진행 중인 동일 조회는 정기 타이머와 화면 복귀 이벤트가 함께 사용한다.
- 첫 조회가 이미 끝났더라도 250ms 안에 이어지는 중복 자동 이벤트를 합친다. 응답 데이터를 보관하는 캐시나 사용자 간 공유 상태는 만들지 않는다.
- 저장 후 명시적 재조회와 HTTP 409 충돌 복구는 진행 중인 옛 조회를 취소하고 새 조회를 시작한다. 옛 응답의 적용도 차단한다.
- 내 팀 화면에서 닉네임 변경 등 작업을 시작하면 이전 조회를 무효화하고 작업 중 자동 조회를 억제한다.
- GET이 계속 대기해 이후 갱신을 막지 않도록 15초 후 취소하고 다음 정기 주기에서 재시도한다. 병렬 조회 중 하나가 실패한 경우 나머지 미완료 조회도 정리한다. POST/PUT/PATCH/DELETE에 조회용 시간 제한이나 자동 재시도를 적용하지 않는다.
- 팀 화면 3초, 내 팀 화면 15초의 타이머 주기는 유지한다. 대회 조회 주기·정적 파일 경로·서버 API·DB 스키마·인증 정책은 변경하지 않는다.

구현: `lib/client-read-coordinator.ts`, 적용: `app/page.tsx`, `components/team-hub.tsx`. 조회 조정기는 각 컴포넌트에서 생성하며 키는 현재 조회 대상만 식별한다. 명시적 재조회·대상 변경·무효화는 이전 작업의 세대를 끝내고 AbortSignal로 요청을 취소한다. 실패·폐기된 결과는 250ms 완료 창에 기록하지 않는다.

## 보호 동작 확인

- 저장 중 room 정기 GET 억제, 저장 완료 뒤 낮은 revision 응답으로 이름이 되돌아가지 않는 기존 동작 유지.
- GET이 진행 중일 때 PUT 409가 발생하면 옛 GET을 공유하지 않고 새 GET을 시작함. 다른 기기의 최신 스냅샷을 표시하고 유지함.
- 내 팀의 account GET이 지연되는 동안 닉네임을 PATCH해도 옛 닉네임으로 덮어쓰지 않음.
- 내 팀의 20초 지연 조회에서 추가 주기가 겹치지 않으며 조회 두 개(account/workspace)를 한 묶음으로 관리함.
- 응답이 계속 멈추면 15초 시간 제한 이후 다시 조회함. 이후 응답이 정상으로 돌아오면 화면 갱신과 지연 안내 해제가 재개됨.
- account 조회 실패 시 대기 중인 workspace 조회가 취소됨.
- HTTP 500 시 기존 주기 재시도는 유지함. 오류 횟수에 따른 재시도 간격 조절은 이번 단계에 포함하지 않음.
