# 요청량 최적화 6단계 — 두 세션 동기화 검증

확인일: 2026-10-21 KST. 통합 브랜치 `codex/claude-request-optimization-final`(원격 main `fc5574b` + Codex 1~5단계 `cec07b48ee9c7ff45d58db5e3833be56b7617f09` 병합). 운영 계정·DB·R2에는 연결하지 않았다.

## 환경

- `npm run cf:build`로 만든 **built Worker**(`dist/server/wrangler.json`, 로컬 설정)를 `wrangler dev --local`로 실행하고 로컬 D1에 마이그레이션 전체를 적용했다.
- `scripts/two-session-fixture.mjs`가 합성 계정 A(주장)·B(팀원)·C(외부)를 넣는다. 세션은 `createKakaoSession`과 같은 방식(토큰 SHA-256 해시)으로 `auth_sessions`에 저장해 앱의 기존 쿠키 인증 경로를 그대로 탄다. 앱 코드에 인증 우회는 추가하지 않았다. 팀 생성·초대·가입 승인은 실제 API로 수행한다.
- 실제 브라우저: Claude 데스크톱 앱 내장 Chromium. A는 `localhost:<port>`, B는 `127.0.0.1:<port>`로 열어 **쿠키 저장소가 분리된 두 인증 세션**을 만들었다(B 호스트는 쿠키 설정 전 `user=null` 확인). 화면 조작은 실제 UI 버튼 클릭이며, 일부 권한 변경·삭제는 같은 세션의 브라우저 `fetch`로 실제 API를 호출했다.
- 요청 시각은 페이지 내 `fetch` 기록과 Resource Timing으로 측정했다. 지연·끊김은 B 페이지의 `fetch`를 감싸 **응답 전달만 늦추거나 실패시켰다**(서버 응답은 실제). 탭 숨김은 이 브라우저 창이 모든 탭을 visible로 보고하므로 `document.visibilityState`를 재정의하고 실제 이벤트를 보냈다.

## 발견·수정한 버그

1. **삭제된 팀(404)을 계속 표시·조회**: 4단계는 401/403만 화면을 정리했다. 팀이 삭제되면 B는 삭제된 팀 데이터를 그대로 보며 15초마다 404를 무한 조회했다. `app/page.tsx`에서 404도 접근 회수로 처리해 화면을 정리한다. 실제 브라우저 재현 → 수정 후 재검증, jsdom 경합 시나리오 `deleted-team-404-clears-room` 추가.
2. **시간 제한과 같은 시각의 조회가 만료 직전 요청에 합류**: 15초 주기에서 정기 조회가 GET 15초 제한보다 약 1ms 먼저 실행돼 곧 중단될 요청을 공유했고, 재시도가 30초로 밀렸다(진행 중 3초 주기에서도 같은 위상에서 한 주기 지연). `lib/client-read-coordinator.ts`는 만료 1초 이내의 요청에 새 조회를 합류시키지 않고 새로 시작한다. 단위 테스트 추가(이전 구현에서 실패 확인), 실제 브라우저에서 재시도 15.0초 확인. 허브의 `hub-slow-20s` 기대값은 30초 동안 계정/워크스페이스 각 2회 → 3회(15초마다 재시도)로 갱신했다.

## 미검증·한계

- **실제 카카오 OAuth 로그인**: 합성 세션을 사용했다. OAuth 왕복·실제 계정은 검증하지 않았다.
- **실제 모바일 기기**: 이 Mac에는 iOS 시뮬레이터(Xcode)가 없고 실기기 연결도 없다. 내장 브라우저의 모바일 에뮬레이션만 확인했다. iOS Safari의 백그라운드 탭 타이머·bfcache 동작은 미검증.
- **실제 탭 숨김**: 내장 브라우저가 탭을 숨김으로 보고하지 않아 visibility 신호를 재정의했다.
- **네트워크 지연·끊김**: 브라우저 내부에서 응답 전달을 지연·실패시켰다. 실제 셀룰러 품질·TCP 재전송은 재현하지 않았다.
- 팀 화면의 정기 조회 오류 문구는 팀 열기 화면에서만 표시된다(기존 동작, 변경하지 않음). 팀 내 화면 전환용 "코드로 열기" 창은 UI 진입점이 없어 팀 전환은 `/teams` 이동으로만 검증했다.
- 운영 Worker 요청·D1 사용량 변화는 배포 후 관찰 대상이며 여기서 측정하지 않았다.
